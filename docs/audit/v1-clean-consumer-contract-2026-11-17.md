# Clean consumer contract for the Win64 source-engine package

This is an implementation proposal for GitHub #16 under [ARC13](../architecture.md#arc13--build-install-and-packaging) and the [supervised package design](../design/v1-guide-and-package.md#v1-supervised-package). Run the same smoke check in a fresh Blueprint-only project and a fresh C++ project against the exact Win64 ZIP built for the pinned Unreal Engine 5.8.4 source distribution. The [existing package evidence](../release-1.0.0.md#current-evidence) records a successful BuildPlugin run and archive verification. The two consumer results remain pending. Launcher and other installed distributions have separate [acceptance requirements](../installed-engine.md).

## Keep the development and installed checks separate

The development [launcher](../../Tools/start-editor.ps1) derives the repository from the project directory's parent, authorizes that repository, checks the DLL under the project's own Binaries/Win64, and uses TestProject fixture and lease paths. The supervised [MCP probe](../../Tools/check-mcp-server.py) reads the development lease and .agent/build-provenance.json before connecting. Its PID fallback establishes whether an editor process is alive. The [development identity check](../../Tools/plugin_identity.py) expects the tracked descriptor and AdditionalPluginDirectories. Passing a different .uproject to these tools would still exercise those assumptions. Use a separate bounded consumer driver and installed identity functions while preserving development launch and verification behavior.

The existing [supervisor](../../Tools/execute-tests.py) already serializes the repository, canonical engine root and port 8000, checks for existing engine processes, and runs each command in its own Windows Job Object. The [child admission](../../Tools/execution_runtime.py) checks the live ancestor, context token, repository and engine. Use those controls and the existing lease refusal. The consumer has no TestProject fixtures to restore. Keep the pending-recovery admission check and leave the current TestProject snapshot and recovery behavior in place for existing profiles.

## Admit and install the exact ZIP

1. Add a closed consumer profile with two fixed phases, BP-only followed by C++. The plan records the checkout commit and digest plus a consumer_artifact object with directory, source_commit, archive_sha256 and manifest_sha256. Require the full commit and both full digests. Reject this object for every other profile. Refuse suites, custom command arguments, alternate ports and alternate project paths. The artifact name selects one direct ordinary child of release/artifacts in the admitted checkout. Refuse paths, traversal, UNC, links and reparse points. A package from an older source can be tested if requested by exact identity. Record its source separately from the harness revision and attribute the result only to that package.
2. Under the supervisor's locks, validate the ordinary .local and .local/executions ancestors before creating a fresh run directory identified by the supervisor's 32-character hexadecimal run ID. Refuse non-directory, redirected or linked ancestors and any existing run or project destination. Write the context and run output only after this check. Read the ZIP and manifest as ordinary files. Compare their hashes against the approved plan before trusting manifest fields or extracting data. Require the ZIP's expected basename, source commit, plugin tree at that commit, Win64 platform, source-build distribution, engine version and engine revision from the [engine lock](../../engine.lock.json). Verify the actual engine checkout, tracked cleanliness and Build.version. Check the descriptor, packaged TurboMCP module receipt, DLL hash, license and notices against the verified package manifest and require its BuildId to match the actual engine's UnrealEditor.modules.
3. Extract directly to each fresh run-owned project under Plugins/TurboMCP. Use the manifest's complete file list as the allowlist. Check paths before creating any file. Reject absolute or escaping paths, ADS/device names, trailing dots or spaces, case-folding collisions, duplicate entries, file-directory collisions, links, reparse points and special files. Require a single TurboMCP top-level directory, exact entry names and lengths, bounded total extraction, and matching streamed hashes. Open destinations exclusively and recheck the installed file set and SHA-256 values. Apply the same collision and containment checks to project files, intermediate paths, configuration and logs. Original ZIP and manifest are read-only inputs and remain outside every launched project.
4. The child accepts only its fixed phase. It rechecks the live supervisor context plus the ordinary run report's active consumer command and artifact identity before using the engine, following [package-plugin.ps1's admission pattern](../../Tools/package-plugin.ps1). Derive its project directory from the owned run and fixed phase rather than accepting .uproject or output paths. Retain generated trees and evidence under the ignored run directory for review. No shared fixture, engine-wide plugin directory or persisted user setting is part of the writable test boundary.

## Run both projects on the same engine

Both generated descriptors enable TurboMCP in their ordinary project Plugins directory. Preserve the archived descriptor and its declared dependency chain. Use fresh local Config, Content, Saved, Intermediate and Binaries paths with no AdditionalPluginDirectories, AdditionalRootDirectories, inherited workspace fixtures or alternate plugin mounts. Before launch, verify exactly one discoverable TurboMCP descriptor under that project's Plugins directory and refuse any matching module or descriptor elsewhere in project or engine discovery, including renamed descriptors.

Write only the generated project's DefaultEditorPerProjectUserSettings.ini for activation. The sections are [/Script/TurboMCP.TurboMCPSettings] with bEnableTurboMCP=True and bEnableCallLog=False, and [/Script/ModelContextProtocolEngine.ModelContextProtocolSettings] with bAutoStartServer=True, bEnableToolSearch=True, ServerPortNumber=8000, ServerUrlPath=/mcp. Disable AutoSave using the generated project's [/Script/UnrealEd.EditorLoadingSavingSettings] section. In its DefaultEngine.ini set [HTTPServer.Listeners] to DefaultBindAddress=127.0.0.1 and DefaultReuseAddressAndPort=False, and clear inherited ListenerOverrides for this test project before startup. Startup samples the TurboMCP setting once. The real listener still needs independent verification. [TurboMCP settings](../../Plugins/TurboMCP/Source/TurboMCP/Public/TurboMCPSettings.h), [startup](../../Plugins/TurboMCP/Source/TurboMCP/TurboMCPModule.cpp), [development MCP settings precedent](../../TestProject/Config/DefaultEditorPerProjectUserSettings.ini).

The module selection in pinned UBT TargetDescriptor.cs and BuildMode.cs limits the build output request to ConsumerCpp. Prerequisites can still run. Require build evidence that only the consumer module was compiled or linked, verify engine identity and package bytes again, and fail a run that compiled or relinked TurboMCP or an engine module. Record an inconclusive build log as missing evidence. In the pinned BuildMode.cs, -NoEngineChanges protects existing engine files and does not rule out new outputs. The stock descriptor's Installed bit does not mandate precompiled project rules. In pinned RulesCompiler.cs the project rules assembly sets read-only using IsProjectInstalled. Avoid using an unfiltered full target build or mistaking -WriteOutdatedActions for a read-only plan. Pinned BuildMode.cs deletes outdated produced items before exporting that action graph.

For both phases use the exact engine executable, the owned project working directory, an explicit run-local log and bounded startup and RPC deadlines. Preserve the ordinary editor startup path with rendered prerequisites available. Place harness temporary files and supported DDC overrides under that project's run directory. The existing Job Object bounds descendants and runtime. These controls do not turn the engine into an OS or network sandbox. After each phase exit and job teardown, verify that no editor from the phase still owns port 8000 before advancing. Stop only through the retained process handle or the phase's Job Object. Record forced stop separately from shutdown behavior.

## Verify loaded identity before each live request

Require a still-live process handle from the current Job Object's launch, matching the pinned executable and exact .uproject argument. Use Windows listener ownership evidence, such as Get-NetTCPConnection, to require that every listening row on that port is loopback and belongs to this exact editor PID. Refuse unavailable or ambiguous process, module or socket enumeration. A port response, process name or MCP session ID alone supplies no ownership evidence. Recheck ownership before requests and fail if it changes. Never reuse an editor, skip the owner check, stop a foreign process or route the test through a proxy or redirect.

Enumerate loaded modules for that PID before MCP discovery. Require exactly one UnrealEditor-TurboMCP.dll from the canonical installed project path and compare its SHA-256 to both the archive entry and the validated manifest. Use separate installed identity inputs and the existing binary verification primitive. A loaded DLL from the development checkout, TestProject, engine plugins, another project or a second candidate fails regardless of registration. Keep the loaded C++ DLL evidence distinct from the packaged plugin DLL evidence.

## Probe the installed tools

Use a fresh session at http://127.0.0.1:8000/mcp. Follow the existing [registry protocol](../../Tools/check-mcp-server.py). Call initialize, tools/list and the bare list_toolsets meta-tool, and require all four TurboMCP toolsets. Use describe_toolset with toolset_name to check the Read and Edit schemas for the following tools before using call_tool with a JSON arguments object.

Use the exact test-only package /Game/TurboMCPConsumer/BFL_InstallSmoke and object /Game/TurboMCPConsumer/BFL_InstallSmoke.BFL_InstallSmoke in each fresh project. This recipe requires no copied .uasset.

1. ReadTurboMCPAssetDescribe with Assets set to the exact object must report zero described and an exact identity refusal. Verify there is no corresponding file under Content.
2. EditTurboMCPFunctionLibraryCreate with PackagePath set to the exact package must report successful creation, the canonical object and generated class, and no disk save. An error or partial result fails even if its first line reports changed.
3. Read the same exact object independently with ReadTurboMCPAssetDescribe. Require one described, class Blueprint, parent /Script/Engine.BlueprintFunctionLibrary, the exact generated class ending in BFL_InstallSmoke_C, loaded yes and unsaved changes yes. These fields come from the live asset and package under [the read implementation](../../Plugins/TurboMCP/Source/TurboMCP/TurboMCPAssets.cpp#L192).
4. Repeat the create command deliberately after step 3 and require its expected unchanged result with a destination-already-exists refusal. Read again and require the same exact fields. Verify Content's file inventory still matches the initial empty inventory. Creation and refusal have distinct source outcomes in [the factory tool](../../Plugins/TurboMCP/Source/TurboMCP/TurboMCPFunctionLibraryCreate.cpp).

A lost or ambiguous mutation response ends the phase with an unknown outcome. Preserve the evidence and inspect the owned disposable project if needed. The deliberate duplicate check follows a confirmed successful edit. There is no transport-driven replay. This smoke check exercises installation and live behavior without saving an asset to disk. Save, reload, undo, captures and broader tools remain separate acceptance work.

## Evidence and refusal controls

After each phase's Job Object is closed, rehash the original ZIP and manifest, including after a failed or timed-out child. Once extraction has completed, verify the entire installed plugin tree against the manifest, including files not used by the smoke test. Extra, missing or changed files fail the phase even when the DLL loaded. Preserve actual stage verdicts and timeouts. Report the harness and package source commits, ZIP/manifest/DLL hashes, engine commit/version/BuildId, installation paths and inventories, C++ build command and actions, editor executable/PID, listener evidence, loaded module path/hashes, MCP call outcomes and checked read-back fields. Retain bounded logs and run evidence locally. Treat missing prerequisites or identity as blocked, checked mismatches and wrong tool results as failures, and scope any passing result to the exact package and engine.

- Offline admission controls cover malformed plan, wrong profile or phase, mismatched archive/manifest digest, engine/source/tree/BuildId mismatch, ZIP traversal and case collision, linked boundaries and pre-existing projects. Refuse before launch or extraction where the check can be made first.
- Installed identity controls use synthetic module and listener observations. Reject the right module name at the wrong path, wrong bytes at the right path, duplicate plugin discovery, an inaccessible module list, a live editor paired with a different listener PID, a wildcard bind and a port contender. These refusals send zero editor MCP requests and stop no foreign process.
- Use native negative controls only when an exact additional check is needed. Test digest mismatch and a foreign loopback port holder using owned synthetic copies or a supervisor-owned dummy process. Never corrupt the accepted archive, start another editor on the contested port or tamper with an engine-wide plugin directory. A simulated child timeout must preserve an unrelated sentinel process and leave only ignorable, run-owned output.
