> DECIDED BY THE OWNER on 2026-10-17. This is no longer an open question. Evidence: Release/EVIDENCE/S04/compile-rule-restored.md and Release/ARCHITECTURE.md.
>
> === THE DECISION (D-008) ===
> An empty graph name NEVER means "take the first graph". The contract is asymmetric, for the same reason the ambiguity rule is asymmetric:
>
> 1. MUTATING tools (Patch, Replace, and every other writer) REFUSE an empty graph name with the code `graph_name_required`, naming the asset and the graphs the caller could have named. A write must not land somewhere the caller did not name.
> 2. READER and ANALYSIS tools treat an empty graph name as "EVERY graph in the asset". Their report must name each graph scanned and its own counts. A reader that cannot honestly produce an asset-wide answer must refuse rather than answer about one arbitrary graph.
> 3. No tool may silently resolve to the first graph. `TurboMCPNodeId::FindGraphByName` keeps its current refusal of an empty name; asset-wide scanning is an EXPLICIT iteration at the call site, never an empty-name guess.
>
> === WHY THIS ANSWER ===
> The previous round recorded a used convention and left the choice open: five call sites pass "" and today get the first graph. Taking the first graph is the behaviour an ambiguous node id cannot express, so it cannot survive a release whose identity contract is ARC06. Refusing in readers would break real asset-wide intent (a comment sweep or a dead-node sweep over an asset is a legitimate request), so readers keep the capability but make it explicit and self-describing.
>
> === IMPLEMENTATION, IN THIS ORDER ===
> 1. TurboMCPGraphPatch.cpp and TurboMCPGraphReplace.cpp: delete their inline candidate lists and delegate to TurboMCPNodeId::FindGraphByName, then refuse an empty name with `graph_name_required`.
> 2. Add the explicit all-graphs path to the readers that need it (comment sweep, graph check, dead-node analysis). It iterates the blueprint's graph arrays, labels every section with its graph name, and sets `complete=false` if any graph could not be read.
> 3. Update the five call sites deliberately, one at a time, choosing refusal or the asset-wide path - never a third meaning:
>      test-comments.py:139, :160, :189 (writers: must name a graph)
>      test-graph-check.py:205 (reader: asset-wide path)
>      test-graph-dead.py:309 (reader: asset-wide path)
> 4. Cases: an empty name on a writer refuses with `graph_name_required`; an empty name on a reader names every graph and its counts; a named graph still behaves exactly as before.
>
> === NON-GOALS ===
> No change to graph-name semantics for a NON-empty name. No new mutator. The MULTIPLE-MATCH refusal remains a separate item (card f70b1508-3213-4a9d-8c81-07615519e26a closed its specification step; the mutator half exists only in GraphRepoint).
>
> === ACCEPTANCE ===
> G-series identity cases plus the D-008 cases above. A pass requires the writer refusal and the reader's asset-wide report to be observed on a real asset, not inferred from source.
