## Current review

2026-10-24: source review found that TurboMCPLocalVars::Apply creates a local and getter, rewires every output consumer and destroys the original calculation, but creates no assignment. It therefore cannot preserve the calculated value. Pure-node classification also does not establish determinism; the visited set can misclassify shared ancestry as a cycle, and multiple outputs are collapsed into a single getter.

Partial safeguard a7480b0: candidate edits are refused before mutation; help and preview no longer promise safe promotion. This is NOT a complete feature repair. Promotion remains unavailable. Implementation status stays open; validation is separate.

## Required completion

Implement a bounded, semantics-preserving promotion with explicit value assignment, correct execution placement, per-output identity, deterministic eligibility and transactional failure handling. Refuse unsupported control-flow or value-lifetime cases with specific reasons. Preserve unrelated graph state. Do not re-enable the old transformation.

Add a disposable native fixture with an actual repeated calculation and independent result/link checks, including rejection and failure controls. Existing test-local-vars only exercises no-candidate/refusal paths. Repair its missing FunctionAdd inputs/outputs arguments without weakening assertions.
